# ДаРэчы (DaRechy)

> «Пытай — адкажа». ИИ-проводник по государственным услугам Беларуси: понятный портал, Telegram-бот с голосом, режим киоска в холле исполкома. Отвечает **только по официальным нормативным актам** — с цитатой пункта под каждым ответом. Нет источника — честный отказ.

**Цель:** рабочее демо к зональному туру «100 идей для Беларуси» — **20.11.2026**.

**Документы:**
- [План разработки](docs/план-разработки.md) — скоуп, стек, недельный план, гейты
- [Концепция заявки](docs/концепция-заявка.md) — аргументация для жюри, риски, питч
- [База знаний: как пополнять](kb_corpus/README.md) — конвейер нормативки

## Каналы MVP

| Канал | Что это | Для кого |
|---|---|---|
| **Портал** | Веб-сайт: «жизненные ситуации» человеческим языком, страницы услуг с чек-листами и цитатами актов, встроенный ассистент | Все, у кого есть интернет |
| **Telegram-бот** | Тот же ассистент в мессенджере: текст + голосовые сообщения (вход и выход) | Основная масса, быстрый доступ |
| **Киоск** | Портал в полноэкранном режиме на терминале в исполкоме/МФЦ: крупный шрифт, микрофон, автоозвучивание | Пожилые, «офлайн» люди |

## Принципы проекта (не обсуждаются)

1. **Каждый ответ — с цитатой** нормативного акта (название, реквизиты, пункт, ссылка на pravo.by).
2. **Нет источника — нет ответа.** Честный отказ и направление в орган вместо фантазии модели.
3. **Данные не покидают контур:** открытые модели (Qwen3, Whisper, Silero), локальный запуск.
4. **ПДн не храним.** Диалог обезличен, остаётся только анонимная статистика.
5. Ассистент — **информационный слой поверх** госсистем. Никаких интеграций с их бэкендами.

```
│   │   ├── chat/         # RAG-оркестратор с цитатами + роутер услуг
│   │   ├── retrieval/    # гибридный поиск: BM25 + Qdrant (RRF-фьюжн)
│   │   ├── kb/           # парсеры актов (docx/pdf) + ingestion корпуса
│   │   ├── llm/          # клиент Ollama (chat + embeddings)
│   │   ├── bot/          # Telegram-бот (aiogram 3): текст + голосовые
│   │   ├── voice/        # STT (faster-whisper) / TTS (Silero) — неделя 3
│   │   ├── data/         # стабы (каталог услуг до переезда в Postgres)
│   │   └── main.py
│   └── tests/            # pytest: парсер, поиск, оркестратор, API (без сети)
├── frontend/             # Портал + киоск-режим (React + TypeScript + Vite)
├── kb_corpus/            # Правовая база: raw/ (оригиналы актов), curated/ (чанки)
├── eval/                 # Golden set: вопросы + эталонные ответы для регресса качества
├── infra/                # Данные контейнеров (в git не попадают)
├── docs/                 # План, концепция заявки
└── docker-compose.yml
```

## Быстрый старт

### 0. Что нужно поставить (один раз)

| Инструмент | Зачем | Как |
|---|---|---|
| Docker Desktop | Postgres, Redis, Qdrant | `brew install --cask docker` |
| Python ≥ 3.11 | бэкенд | уже есть на macOS |
| Node ≥ 20 | фронтенд | уже есть / `brew install node` |
| Ollama | локальная LLM | `brew install ollama && ollama pull bge-m3 && ollama pull qwen3:1.7b` — почему именно эти, см. [локальная-модель.md](docs/локальная-модель.md) |

### 1. Инфраструктура

```bash
docker compose up -d postgres redis qdrant

# проверки:
curl http://localhost:6333/healthz        # Qdrant
docker compose ps                          # все контейнеры должны быть Up/healthy
```

Стоп: `docker compose down` (данные остаются в `infra/data/`). Полный сброс: `docker compose down && sudo rm -rf infra/data`.

### 2. Бэкенд

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env             # ❗ позже впишем TELEGRAM_BOT_TOKEN

uvicorn app.main:app --reload
```

Проверки:
- http://localhost:8000/health — `{"status": "ok", ...}`
- http://localhost:8000/docs — автодокументация API (Swagger)
- http://localhost:8000/api/services — каталог услуг (пока стаб)

Тесты: `pytest -q` (парсер актов, BM25/RRF, оркестратор с цитатами, память диалога, TTS, API) · Линтер: `ruff check app tests`

Голосовой синтез (TTS, опционально): `pip install -r requirements-voice.txt` — без него бот и портал отвечают только текстом, всё остальное работает. Модель Silero (~100 МБ) скачается при первом синтезе.

Регресс качества (API должен работать): `python3 eval/run_eval.py` из корня репо — прогон golden set, отчёт в `eval/history/`.

Индексация корпуса (после того как появились `kb_corpus/curated/*.json`):

```bash
python -m app.kb.ingest    # чанки → BM25; Qdrant поднят и модель есть → грузятся вектора
```

Без Docker/Qdrant/Ollama всё работает: BM25 + экстрактивные ответы с цитатами (guardrail живой и в деградации).

**Локальная модель:** какие модели качать, почему 1.7b, как настроить `keep_alive` под 8 ГБ RAM — [локальная-модель.md](docs/локальная-модель.md).

### 3. Фронтенд

```bash
cd frontend
npm install
npm run dev
```

Открыть http://localhost:5173 — главная портала. Она тянет каталог услуг с бэка через прокси `/api → :8000` (прокси уже настроен в `vite.config.ts`). Если бэк не поднят, страница покажет предупреждение — так и задумано.

Сборка/проверка перед пушем: `npm run build`

### 4. Правовая база (обоим, с дня 1)

Полный конвейер — в [kb_corpus/README.md](kb_corpus/README.md). Коротко: трекер актов → скачать оригинал в `kb_corpus/raw/` → разобрать в `kb_corpus/curated/*.json` → кросс-проверка вторым напарником → индексация.

## Рабочий процесс (как ведём проект)

1. **Задачи — в Issues.** Недельные гейты уже заведены: см. Issues. От задачи — ветка `feat/<номер>-краткое-имя` (например `feat/7-stt-pipeline`).
2. **PR в `main`,** ревью второго напарника обязательно. Красный CI — не мержим.
3. **Воскресенье, 30 минут** — чекпоинт: сверка гейтов недели из [плана](docs/план-разработки.md), приоритеты следующей.
4. **Секреты** — только в `.env` (в `.gitignore`). В коде токенов быть не должно.
5. Блокирующая задача не живёт дольше суток без сообщения напарнику.
